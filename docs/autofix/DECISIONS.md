| # | Assumption | Change cost |

| A4 | Twilio for SMS, WhatsApp and voice | Medium (behind `MessageChannel`) |
| A5 | Node 22, pnpm 10.12.1, Next 16, React 19, Tailwind 4 as in SOB | |
| A6 | **Garage context in the database.** Admin requests send the member's selected garage to PostgREST as the `x-garage-id` header. `public.current_garage_id()` returns it only if `auth.uid()` is a member of that garage (or the caller is `service_role`), else `null`. Tenant RLS policies are `garage_id = (select public.current_garage_id())`, so a multi-garage user only ever sees the selected garage and a forged header yields zero rows. Tenant `garage_id` columns default to `current_garage_id()` | Low; one helper |
| A7 | Garage admin moves from SOB's `/admin` to `/app` on the admin host; `/admin` is reserved for the Vitalos super admin (P4.5) | Low |
| A8 | Garage booking sites render from `src/app/%5Fsite/[garageId]/…` (URL `/_site/<garageId>/…`, `%5F` because `_folders` are private in the App Router). Only reachable through the proxy rewrite; direct requests to `/_site` return 404 | Low |
| A9 | Migrations: one squashed SOB baseline (SOB-only surfaces removed in P1.1 are left out) plus timestamped Autofix migrations (`<ts>_tenancy.sql`, `<ts>_scheduling.sql`, …). SOB's 30 migrations stay in git history only | Low |
| A10 | Platform-level tables with no garage owner at write time (`rate_limit_buckets`, inbound/Resend webhook idempotency tables, `unmatched_inbound_emails`, MFA/trusted-device tables keyed by user) have no `garage_id`; they are service-role or own-user only, and the tenancy suite asserts staff cannot read them | Low |
| A11 | Customer phone keeps SOB's column name `customers.phone` (E.164) rather than the SPEC's `mobile` to avoid churn; same meaning | Low |
| A12 | Work is committed on the session branch `claude/modest-mayer-9yzmr0` (task commits prefixed with the task ID) rather than merged straight to `main`, because `main` changes need a reviewed PR | Low |
| A13 | **Opt-out and sender IDs.** UK alphanumeric senders (e.g. `HartleyRd`) are one-way, so a customer cannot reply STOP to them. Reminders and other messages that promise "Reply STOP" go from the garage's two-way Twilio number (Messaging Service). A garage may use its alphanumeric sender for booking updates only, and those messages end with an opt-out link (`/unsubscribe`) instead of "Reply STOP" | Low; needs the PECR wording review already on the list |
| A14 | Twilio has no idempotency key: the engine claims the `reminder_sends`/`messages` row before calling `send()` and treats timeouts as ambiguous (not retried automatically) | Low |
| A43 | **CI runs on self-hosted runners.** Every GitHub-hosted run failed in ~2 s because of org billing ("recent account payments have failed or your spending limit needs to be increased"), not a repo setting. CI now runs on `ghrunner-autofix` runners (Azure `autofix-ci` primary, AWS build VM fallback) with `runs-on: ${{ fromJSON(vars.RUNS_ON \|\| '["self-hosted","autofix"]') }}`; first fully green run 40429708549 on 27 Oct 2026. Billing is handled separately; see `infrastructure/RUNNER.md` to switch back | Low |
| A15 | MFA stays enforced in the database for invoice and trash RPCs (AAL2 when the user has TOTP; owners must enrol while mandatory MFA is on, the shipped default). Plain table reads follow membership only, so the app keeps its MFA gate before handing out the RLS client. Trusted-device sessions can read but not call invoice RPCs (as SOB) | Low |
| A16 | `garage_domains.hostname` is unique among non-deleted rows, so a removed domain can be connected again later | Low |
| A17 | Retention no longer anonymises customers who still have bookings or invoices (SOB's job did on its next run). Retention removes storage rows directly; switch to the Storage API in P3.7 so files are deleted too | Low |
| A18 | Invoice numbers are `<booking_prefix>-YYYY-NNNNNN` per garage; invoice issuer details are copied from the garage when a draft is saved/issued | Low |
| A19 | **Admin garage selection.** The selected garage is the httpOnly `af_garage` cookie, honoured only if the user is a member of that garage; otherwise (missing, forged, stale) the user's oldest membership is used. Cancelled garages and unknown roles are not memberships. A user with no membership cannot sign in. Switching garage reloads `/app` | Low |
| A20 | Mandatory MFA stays app-wide for every garage member, as SOB had it for admins (the database only requires it for owners). Account security events (MFA, trusted devices, password change) are written to the audit log of every garage the user belongs to, and nowhere when they belong to none | Low |
| A21 | **Email identity.** Every email is sent from the platform sender (`RESEND_FROM_EMAIL`, e.g. `notifications@autofix.vitalos.co.uk`) with the garage's name as display name, `Reply-To` the garage's email (enquiry replies use the per-thread reply address). Staff alerts go to the garage's email when it has one. Footer: "Sent by Autofix on behalf of <garage>". Auth emails (password reset) are Autofix-branded, not per garage | Low; needs the Resend domain already on the list |
| A22 | Invoice bank details live in `garages.settings.invoicePayment` (`accountName`, `sortCode`, `accountNumber`); without them the PDF has no bank block. Garage logos are used only from `https` URLs (PNG/JPEG ≤ 1.5 MB); otherwise the garage name is shown | Low |
| A23 | Unmatched inbound email (no valid reply token) stays in `unmatched_inbound_emails` with no garage; the garage-admin triage page is removed and triage moves to the super admin (P4.5) | Low |
| A24 | The retention cron runs `apply_enquiry_retention` once per garage, cancelled garages included, and reports totals only. Opening hours now live in `opening_hours` (P2.1); anything still read from `site_settings.value` for hours is stale | Low |
| A25 | **Tenancy test helpers ship as a migration.** `20261026000200_tenancy_test_support.sql` adds read-only, service-role-only catalogue functions (`tenancy_tables()`, `tenancy_policies()`, `tenancy_function_grants()`, `tenancy_fingerprint()`, `tenancy_sample_row()`, `tenancy_storage_fingerprint()`) so the Gate 1 suite runs the same way locally and in CI. They expose nothing the service role cannot already read, and pgTAP 009 asserts anon/authenticated cannot execute them | Low; drop the migration's functions if a hosted DB must not carry them |
| A26 | **Every new `garage_id` table needs a tenancy fixture.** The suite fails with "no fixture for table X" until `FIXTURES` in `tests/integration/tenancy.test.ts` can create a row of it in a garage (service role or the proper RPC) | Low |
| A27 | **CI isolation per runner.** Runners share one machine, so each CI job takes Supabase project `autofix-ci-<N>` (ports +N*100) and app ports 3400+N*10+1..4 from `scripts/ci/supabase-isolate.sh`, instead of a shared concurrency group (GitHub keeps one pending job per group and cancels the earlier one) | Low |
| A28 | **SOB wizard e2e until P2.8.** `tests/e2e/booking.spec.ts` runs on the seeded garage host; its three journeys are `fixme` (written for an older SOB wizard: system picker and service checkboxes since) and the hidden mobile h1 is an expected failure (`test.fail`) until the 5-step flow replaces the page | Low; P2.11 replaces the spec |
| A29 | **Scheduling migration rebuilds `bookings`.** There is no production data, so `20261027000100_scheduling.sql` drops SOB's bookings and the Cal.com tables and creates the contract shape; a guard refuses to run if any booking or Cal.com service row exists (reset instead). SOB's `booking_audit_log` and `booking_notification_events` stay and point at the new table; `booking_events` supersedes the audit log | Low |
| A30 | **Phones are E.164 in the database.** `customers.phone` is checked (`^\+[1-9][0-9]{6,14}$`) and unique per garage; anonymised customers have `phone = null` (retention no longer writes `'REDACTED'`). Public enquiries normalise UK numbers with `toE164UK` and reuse the garage's customer by phone and vehicle by registration; a failed enquiry removes only rows it created | Low |
| A31 | **One vehicle row per registration per garage**, owned by its latest customer: `create_booking` moves a matched vehicle to the booking's customer. Booking invoices therefore no longer require the vehicle's *current* customer to be the booking's (`save_invoice_draft`/`issue_invoice` still require the booking's own customer and vehicle to match the invoice). SOB's `fuel_type` is renamed `fuel` | Low |
| A32 | **Mobile visits use mobile resources.** `services.resource_kind` is the workshop resource; a mobile visit (service `mobile` or `both`) always takes a `mobile` resource and blocks `garages.mobile_travel_min` before and after. Opening hours bound the appointment, not the travel | Low |
| A33 | **Engine errors.** `available_slots` raises `SERVICE_UNAVAILABLE`/`INVALID_BOOKING` (P0001) like `create_booking` rather than returning no rows; suspended and cancelled garages have no slots; MOT services exist for every garage and are hidden until `mot_enabled` | Low |
| A34 | **Consent at booking.** Ticking the box records `reminder_consent`, `consent_at`, `consent_source` (default `booking`) and `consent_text` together, only when the customer has no consent on record; an unticked box never withdraws consent, and `create_booking` never touches `opted_out_at` (STOP/unsubscribe own it). A new tick after an opt-out is recorded but sending stays blocked by `opted_out_at` | Low; part of the PECR review already on the list |
| A35 | **Booking status trail by trigger.** Every status change writes a `booking_events` row (`staff` + member id via the RLS client, else `system`); `cancelled_at` follows `status`. Only cancelled, no-show or collected bookings can be trashed (a live booking holds its resource); the trash's catalogue entities became `services` | Low |
| A36 | **Clock-injectable engine.** `available_slots_at()`/`create_booking_at()` take `p_now` so pgTAP can test fixed dates (the 2026 clock changes are already past); they are granted to no API role. Bookings per garage are allocated under a transaction advisory lock; `no_overlap` remains the final check | Low |
| A37 | **Known gap for P3.11:** `apply_enquiry_retention` anonymises any customer with no recent enquiry, booking or invoice (behaviour since P1.4). Customers imported without bookings would be anonymised by the next retention run; P3.11 must exempt consented/imported customers before imports go live | Medium; needs a retention rule decision |
| A38 | **Manage links.** The manage-link token is derived (HMAC over garage id + idempotency key) rather than random, so an idempotent replay and later emails carry the same link; only its SHA-256 is stored. Rotating `BOOKING_MANAGEMENT_SECRET` keeps existing links working but later emails for older bookings fall back to the plain `/manage` page. Without the secret in production, booking creation answers `UNAVAILABLE` | Low |
| A39 | **Customer changes online.** Customers may reschedule or cancel `requested`/`confirmed` bookings until `garages.cancellation_cutoff_h` before the start; staff are not bound by the cutoff. A customer reschedule keeps the status (no re-approval) and only offers starts `available_slots()` offers | Low |
| A40 | **Public booking input.** `POST /api/bookings` bodies are strict: `garageId`, `source` and `reminderSendId` are rejected (422), `source` is always `online`. Customers must give a UK mobile (stored E.164); mobile visits need an address and a valid UK postcode. Turnstile is enforced whenever `TURNSTILE_SECRET_KEY` is set. SOB's limits are kept: 5/10 min per IP, 200/10 min per garage, 5/30 min per IP + phone | Low |
| A41 | **Booking messages respect `MESSAGING_MODE`.** Booking emails, SMS and WhatsApp all go to the mock outbox unless `MESSAGING_MODE=live` (enquiry/invoice email is unchanged). Booking texts are service messages: sent straight away (no quiet hours), only on the customer's chosen channel, never after `opted_out_at`, from the two-way number (no alphanumeric sender, A13). A new booking's text for a `requested` booking says the garage will confirm | Low |
| A42 | **Schema assumptions the API lane codes against** (for the P2.1 SQL): `bookings` keeps `deleted_at` (trash) and `booking_notification_events` stays; `booking_events.at` defaults to `now()`; PostgREST can embed `services`, `resources`, `customers`, `vehicles` from `bookings`. `create_booking()` may add `replayed: true` (or `created: false`) to its result for idempotent replays; the app also pre-checks the key | Low |
| A44 | **Legal copy comes from the drafts, not retyped.** `scripts/sync-legal-copy.mjs` embeds `docs/autofix/legal/*.md` in `src/lib/legal/sources.generated.ts`; the app renders that Markdown and `src/__tests__/legal-copy.test.ts` fails if the two differ or a UI string drifts from its quote. Pages keep the draft's version and a visible "Draft vX, pending solicitor review" flag until the solicitor's final text drops the "(draft …)" heading suffix and draft line. Garage placeholders are filled from Settings; a missing detail shows as "[address not provided]" rather than a guess; a missing legal name falls back to the trading name. The privacy notice's "Last updated" is `PRIVACY_NOTICE_UPDATED` in `src/lib/legal/documents.ts` (bump with the draft) | Low; solicitor review already on the list |
| A45 | **Unsubscribe links.** `/unsubscribe/<token>` on the garage host (not the draft's `/r/{token}/stop`, which clashes with P3.9 reminder links); token = customer id + 128-bit HMAC-SHA-256 over garage and customer, keyed by `BOOKING_MANAGEMENT_SECRET` with its own context label, no expiry, nothing personal in the URL. Opening the link opts out at once (link scanners may opt someone out; that errs on the safe side) and is idempotent. "Turn reminders back on" works from a signed link only and records consent (`consent_source = 'unsubscribe_page'`, the shown wording). The no-link form answers the same whatever the number, 5 tries/10 min per IP and 100/10 min per garage. A web opt-in does not lift a STOP held by Twilio/the carrier (the customer texts START) | Low |
| A46 | **Consent wording draft v0.2** adds the MOT-off checkbox text, the unsubscribe page states and the "Stop reminders: {unsubscribe_link}" line, and corrects `consent_source` to `'booking'`. The wording version is identified by the stored `consent_text` itself (no separate version column) | Low; part of the PECR review |
| A47 | **DPA acceptance.** `garage_agreements` (garage, kind `dpa`, version, SHA-256 of the DPA with the garage's legal name filled, accepted by/name/role/at), written only by `accept_garage_agreement()` (service role; the database re-checks the user is an owner), one row per version, never updated. A new DPA version shows as not accepted until an owner accepts it. Nothing blocks bookings while it is unaccepted (owners see a prompt on `/app/settings/agreements`); sign-up (P4.4) should require it by reusing `DpaAcceptance` and `acceptDpaAction` | Low |
| A48 | **Opt-out audit trail** is `admin_audit_log` (`customer.opted_out` / `customer.opted_in`, `actor_id` null, `detail.source`), written by `opt_out_customer()` / `resume_customer_reminders()` in the same transaction and shown in the dashboard's Recent activity. Customer booking emails carry "Privacy notice" and the customer's own "Stop reminders" link in the footer. `composeBookingNotifications` can send SMS from an alphanumeric sender (`smsSenderId`), replacing "Reply STOP" with the link (A13), but no caller passes it yet, so A41 (two-way number) still holds | Low |
