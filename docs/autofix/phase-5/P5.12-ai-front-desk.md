# P5.12 AI front desk on Pro

D17 moves the AI front desk (the Workforce agent on calls and WhatsApp, with a monthly minutes allowance) to **Pro** (feature key `ai_front_desk`). **Essentials** keeps missed-call text-back, voicemail and the Askbridge website chat, unchanged.

What changed:

1. The agent tool API (`/api/agent/v1/*`) refuses a **Workforce** token whose garage is not on Pro with 403 `{code: "PLAN_REQUIRED", feature: "ai_front_desk", plan: "pro", message}`, before scopes, and audits the refusal in `agent_call_log`. **Askbridge** tokens keep working on Essentials, limited to read-only tools.
2. The Twilio voice webhook has a **hand-off hook**: where a call is missed, a Pro garage with the front desk switched on is put through to the Workforce voice agent over SIP (when `WORKFORCE_VOICE_SIP_URI` is set). Essentials, switched off, unconfigured, or a failed check: exactly the P4.1 flow.
3. Workforce reports minutes with a new tool, `POST /api/agent/v1/report_usage`, recorded as `ai_minutes` through `recordUsage()` (source key `ai:<conversationId>`). Never blocks; the existing month close records any overage.
4. New page `/app/settings/ai-front-desk` (Setup nav, Pro badge when locked): the owner's switch, the Workforce connection, Workforce tokens (raw token shown once, list, revoke) and this month's AI minutes. Essentials garages see `ProLockedPage` and a line saying missed calls still get a text back.
5. Settings, Plan already shows AI minutes for Pro garages (P5.2); the new page reads the same `garage_usage_month()` row for the same garage-local month (`usageMonthFirst()` = the Plan page's `monthStart(localDateKey(now, tz))`, unit-tested on the clock-change days).

Voice flow additions (`POST /api/webhooks/twilio/voice`):

| Request | Event key | Writes | Answer |
| --- | --- | --- | --- |
| incoming call, no own phone to ring (or our forward came back), **hand-off on** | `voice:<CallSid>:<status>` | `calls` row `missed = true`; **no** `calls.text_back` | `<Dial timeout=20 answerOnBridge action=?step=agent><Sip>$WORKFORCE_VOICE_SIP_URI?X-Autofix-Garage=<garage id>&X-Autofix-Call-Sid=<CallSid></Sip></Dial>`; outcome `call_ai_front_desk` |
| `?step=dial` missed (busy/no-answer/failed/canceled), **hand-off on** | `voice:<CallSid>:dial` | `dial_status`, `missed = true`; no text-back | the same `<Sip>` dial; outcome `dial_missed_ai_front_desk` |
| `?step=agent` (`DialCallStatus` of the Workforce leg) | `voice:<CallSid>:agent` | missed statuses: `calls.text_back` queued (by CallSid → call id) | missed: the voicemail TwiML (`agent_missed`); answered: `<Hangup/>` (`agent_answered`) |

"Hand-off on" = `WORKFORCE_VOICE_SIP_URI` valid **and** `ai_front_desk_hand_off(garage)`; if the check throws, the Essentials flow runs (a call is never lost to it). The garage's own phone is still rung first.

**WhatsApp**: no hand-off in code. The hook point is `inbound()` in `src/lib/messaging/twilio-webhooks.ts`, after the inbound WhatsApp message is stored: for a garage where `ai_front_desk_hand_off()` is true, queue a job that forwards the stored message to Workforce's WhatsApp endpoint (signed, like the Askbridge sync), and Workforce replies through the agent API / messages pipeline. Not built until Workforce publishes that endpoint (Waiting on Temitope). Until then WhatsApp behaves as today on every plan; Workforce still reports any WhatsApp minutes with `report_usage` (`channel: whatsapp`).

## Assumptions

| # | Assumption | Risk |
| --- | --- | --- |
| A382 | Existing agent tokens are classified by what they can do: scopes ⊆ {`list_services`, `available_slots`, `garage_profile`} → `askbridge` (keeps working on Essentials), anything that can look up a vehicle, book or read a booking → `workforce` (needs Pro). New tokens default to `workforce`. Askbridge does not call the agent API today, so the read-only set is our choice | Low: production has few or no tokens; a mis-classified token can be revoked and reissued on the settings page |
| A383 | Workforce tokens that held all six P4.2 tools gain `report_usage`; narrower ones do not (reporting minutes affects the garage's bill). The null-scope default of `issue_agent_token()` stays the six tools (P4.2 contract and pgTAP 018); tokens issued from the app get all seven | Low |
| A384 | `report_usage` uses the API's camelCase (`conversationId`, `endedAt`) like every other tool, not snake_case. A conversation counts once: a repeat returns the first figure with `replayed: true`, even if the minutes differ. Minutes are rounded to 0.01 and capped at 600 per conversation; `endedAt` must be in the last 31 days (a late report counts in the month it ended, after that month may already be closed) and not more than 5 minutes ahead | Medium: Workforce may want to send corrections; a correction would need a new tool or a manual adjustment |
| A385 | Workforce identifies the garage from the SIP header `X-Autofix-Garage` and uses the Twilio `CallSid` (`X-Autofix-Call-Sid`) as the call's `conversationId`. The target is one platform-wide SIP URI (`WORKFORCE_VOICE_SIP_URI`), not per garage | Medium: Workforce may prefer a phone number or per-garage endpoints; the hook is one function to change |
| A386 | A handed-off call is logged `missed = true` (nobody at the garage answered) and gets no text-back; if the Workforce leg is not answered, the Essentials fallback (voicemail + text-back) runs. Answered AI calls still appear as missed calls on Today until staff mark them handled | Medium: staff may want AI-handled calls shown differently (needs Workforce call outcomes) |
| A387 | The switch is owner-only (like the booking page and Askbridge); tokens are owners and managers (like `list_agent_tokens()` / `revoke_agent_token()`). Switching off and revoking work on Essentials too, so a downgraded garage can tidy up | Low |
| A388 | A `workforce` token on Essentials is refused before its scopes are checked, and the refusal is audited in `agent_call_log` with outcome `PLAN_REQUIRED`. Tokens are not revoked on a downgrade: upgrading again makes them work at once | Low |
| A389 | `report_usage` always records, even with `USAGE_METERING=off` (that switch is for SMS metering in `meterSmsChannel()`); the AI minutes allowance stays the P5.2 placeholder `PLAN_PRO_AI_MINUTES` (null → "to be confirmed", months closed as not billable) | Low |

## Waiting on Temitope

- The AI front desk minutes allowance in Pro (`PLAN_PRO_AI_MINUTES`) and the per-minute overage price (already on the P5.2 list).
- From Workforce: (1) the SIP URI (or other voice endpoint) Twilio should dial for missed calls, and whether it accepts the `X-Autofix-Garage` / `X-Autofix-Call-Sid` headers; (2) confirmation that it will call `POST /api/agent/v1/report_usage` once per conversation with the CallSid / its WhatsApp conversation id; (3) its WhatsApp hand-off contract (endpoint, signature, how it replies), so the WhatsApp hook can be built; (4) whether it needs a callback when a garage switches the front desk off or drops to Essentials.
- Production `AGENT_TOKEN_PEPPER` must be set in Vercel (it already was a P4.2 requirement); without it the settings page says tokens can't be created yet.
- Twilio: the voice number's SIP dialling to Workforce may need the SIP domain allowed on the Twilio account (account setting; not changed here).
